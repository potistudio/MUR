# MUR Specifications

- **締め切り**: 2026/11/28
- **種別**: ライブパフォーマンス向けVJソフトウェア

## 1. コア要件

1. MIDI信号を受信し、映像・エフェクトをリアルタイム制御できること。
2. 操作画面とは別の外部ディスプレイへ、映像を低遅延に生送信できること。
3. 複数の映像を同時にデコードし、リアルタイム合成・エフェクト適用できること。
4. FHD（1920×1080）60fpsで安定動作すること。
5. ライブ中のクラッシュ・強制終了の経路を可能な限り塞ぎ、異常発生時も出力を継続できること。

## 3. 映像入力・デコード仕様

### 3.1 対応フォーマット

素材は事前変換運用とし、デコード負荷・外部依存・クラッシュリスクを最小化する。

- **動画**: QuickTime（`.mov`）コンテナ内の HAP コーデック
  - `Hap`（DXT1 / BC1、不透明）
  - `Hap Alpha`（DXT5 / BC3、透過対応）
  - `Hap Q`（DXT5-YCoCg、高画質。YCoCg → RGB 変換は GPU シェーダーで実施）
- **静止画**: PNG / JPEG
- **音声トラック**: 無視する（デコード・再生を行わない）

### 3.2 同時デコード数・読み込み戦略

- **同時デコード目標**: 最大 **4 レイヤー同時再生**（FHD 60fps × 4 本）
- **メモリ・I/O 戦略**:
  - 各クリップの**先頭フレームのみメモリ常駐**させ、トリガー時の即時表示（0 フレーム待ち）および UI サムネイルに共用する。
  - 再生中は**非同期ファイル I/O ＋リングバッファ先読み**によるストリーミングデコードを行い、大容量素材でも RAM 枯渇を防止する。
  - HAP フレームは Snappy 展開後、圧縮テクスチャ（BC1 / BC3）のまま GPU へ転送し、CPU 負荷・メモリ帯域を抑える。
- **解像度・アスペクト比が異なる素材の扱い**:
  - デフォルトは**アスペクト比維持フィット**（余白部分は不透明素材なら黒、透過レイヤーなら透明）とする。

---

## 4. 再生制御・合成・エフェクト仕様

### 4.1 レイヤー構成と再生制御（最大 4 レイヤー）

各レイヤーで以下を独立制御できること。

- **再生モード**: ループ再生 / ワンショット再生
- **再生速度変更**: スロー・倍速・逆再生に対応
- **再生状態制御**: 一時停止 / 再開、頭出しリトリガー（先頭フレームへ即時復帰）

### 4.2 レイヤー合成

- 各レイヤーに**不透明度（0.0 〜 1.0）**を設定可能。
- 各レイヤーに以下の**ブレンドモード**を設定可能：
  - `Normal`
  - `Add`
  - `Multiply`
  - `Screen`
  - `Difference`

### 4.3 マスターシェーダーエフェクト

全レイヤーの合成結果（マスター出力）に対して、以下のリアルタイムシェーダーエフェクトを一括適用できること。

- RGB シフト（色収差）
- グリッチ / ブロックノイズ
- ストロボ / 色反転
- 色調補正（輝度 / コントラスト / 彩度）

### 4.4 緊急出力制御・マスター出力調整

- **マスターブラックアウト**: ワンアクションで即座に黒画面へ切り替え、解除時に元の合成出力へ復帰できること。
- **マスターディマー**: マスター出力全体の輝度ゲイン（0.0 〜 1.0）をフェーダーで滑らかにフェードイン / フェードアウトできること。

---

## 5. 映像出力・ディスプレイ仕様

- **出力方式**: 操作用コントロールウィンドウとは別に、選択した外部ディスプレイへ**ボーダーレス全画面ウィンドウ**を表示して映像を送出する。
- **内部レンダリング仕様**: **1920×1080（FHD） / 60fps 固定**。
  - 外部ディスプレイが 4K 等の異なる解像度・アスペクト比であっても、内部の 1920×1080 レンダーターゲットからアスペクト比を維持してスケーリング出力する。
- **出力制御**:
  - コントロール画面から出力先ディスプレイを選択し、出力の ON / OFF を切り替えられること。
  - macOS のメニューバー・Dock・Spaces および HiDPI（Retina）スケーリングを考慮し、外部ディスプレイ全面に正しく配置されること。

## 6. MIDI 入力・マッピング仕様

### 6.1 基本方針（11/28 版）

- **対象デバイス**: **Novation Launch Control XL 3**（8 フェーダー / 24 エンコーダー［3 行×8 列］ / 16 ボタン［2 行×8 列］）
- **接続・動作モード**: **Custom Mode**（USB `MIDI In/Out` ポート使用、**MIDI Channel 1 統一**）
  - Novation Components で MUR 専用テンプレートを作成して本体 Custom Mode スロットへ事前書き込みする運用とする。
  - エンコーダーは **Absolute（0〜127）**、ボタンは **Momentary（押下 Note On / 離鍵 Note Off）** として本体側を設定し、Toggle / Momentary の状態管理は MUR 側で行う。
  - ボタン・エンコーダーの視認用 LED カラーは Novation Components 側で事前固定設定する（11/28 版では MUR からの MIDI Out 制御を行わない）。
- **デバイス管理**: ホットプラグ対応とし、起動中の抜き差しを検知して切断時はバックグラウンドで自動再接続する。

### 6.2 対応メッセージと制御対象

| メッセージ種別 | 制御対象 |
| --- | --- |
| Note On / Off（Ch 1） | クリップトリガー / 頭出しリトリガー、一時停止 / 再開、エフェクト ON / OFF、ブラックアウト切替、エフェクト一括リセット等 |
| Control Change (CC)（Ch 1） | 各レイヤー不透明度・再生速度・ブレンドモード・クリップ選択、マスターエフェクト強度・色調・ストロボ速度、マスターディマー |

### 6.3 Novation Launch Control XL 3 固定マッピング表（MIDI Ch 1）

左 4 列（ストリップ 1〜4）を**レイヤー 1〜4**、右 4 列（ストリップ 5〜8）を**マスターエフェクト＆出力**に割り当てる。

#### 左 4 列（ストリップ 1〜4：レイヤー 1〜4）

| 物理操作子 | 種別 | 番号 | 割り当て機能 | 値・動作 |
| --- | --- | --- | --- | --- |
| フェーダー 1〜4 | CC | `1` 〜 `4` | レイヤー 1〜4 不透明度 | `0〜127` → `0.0〜1.0` |
| エンコーダー Row 1（1〜4） | CC | `11` 〜 `14` | レイヤー 1〜4 再生速度 | 中央 `64` = `+1.0x`（左で減速〜逆再生 `-2.0x`、右で倍速 `+4.0x`） |
| エンコーダー Row 2（9〜12） | CC | `21` 〜 `24` | レイヤー 1〜4 ブレンドモード | `0〜127` を 5 分割（Normal / Add / Multiply / Screen / Difference） |
| エンコーダー Row 3（17〜20） | CC | `31` 〜 `34` | レイヤー 1〜4 クリップ選択 | 読み込み済みクリップ一覧からインデックス選択 |
| ボタン Row 1（1〜4） | Note | `36` 〜 `39` | レイヤー 1〜4 トリガー / リトリガー | Momentary（選択中クリップを発火・再生中なら頭出し） |
| ボタン Row 2（9〜12） | Note | `44` 〜 `47` | レイヤー 1〜4 一時停止 / 再開 | Toggle（押下ごとに一時停止・再開を切替） |

#### 右 4 列（ストリップ 5〜8：マスターエフェクト＆出力）

| 物理操作子 | 種別 | 番号 | 割り当て機能 | 値・動作 |
| --- | --- | --- | --- | --- |
| フェーダー 5 | CC | `5` | RGB シフト強度 | `0〜127` → `0.0〜1.0` |
| フェーダー 6 | CC | `6` | グリッチ / ブロックノイズ強度 | `0〜127` → `0.0〜1.0` |
| フェーダー 7 | CC | `7` | ストロボ / 色反転強度 | `0〜127` → `0.0〜1.0` |
| フェーダー 8 | CC | `8` | マスターディマー（全体出力ゲイン） | `0〜127` → `0.0〜1.0` |
| エンコーダー Row 1（5） | CC | `15` | 輝度（Brightness） | 中央 `64` = デフォルト（増減調整） |
| エンコーダー Row 1（6） | CC | `16` | コントラスト（Contrast） | 中央 `64` = デフォルト（増減調整） |
| エンコーダー Row 1（7） | CC | `17` | 彩度（Saturation） | 中央 `64` = デフォルト（増減調整） |
| エンコーダー Row 1（8） | CC | `18` | ストロボ速度（周波数） | `0〜127` → 低速〜高速 |
| エンコーダー Row 2〜3（13〜16, 21〜24） | CC | `25` 〜 `28`, `35` 〜 `38` | 予備（拡張エフェクトパラメータ用） | 未割当 |
| ボタン Row 1（5） | Note | `40` | RGB シフト ON / OFF | Toggle |
| ボタン Row 1（6） | Note | `41` | グリッチ / ブロックノイズ ON / OFF | Toggle |
| ボタン Row 1（7） | Note | `42` | ストロボ / 色反転 ON / OFF | Toggle |
| ボタン Row 1（8） | Note | `43` | マスターブラックアウト | Toggle |
| ボタン Row 2（13〜16） | Note | `48` 〜 `51` | 予備（エフェクト一括リセット / クイック発火等） | 実装時に必要に応じて割当 |

## 7. コントロール画面（UI）・データ管理仕様

### 7.1 操作ウィンドウ構成

操作側ディスプレイに表示する UI には、以下の要素を最小構成として備える。

1. **マスター出力ミラープレビュー**: 外部ディスプレイ送出映像の縮小リアルタイム表示。
2. **4 レイヤー操作パネル**: 各レイヤーの再生状態、不透明度、ブレンドモード、再生モード、再生速度、リトリガー操作。
3. **クリップグリッド**: 読み込み済み素材の**先頭フレームサムネイル＋ファイル名**を一覧表示し、クリックで対象レイヤーへ即発火できること。
4. **マスターエフェクト操作パネル＆ブラックアウトボタン**: 各エフェクトの ON / OFF・強度調整および緊急ブラックアウト。
5. **ステータスバー**: 出力先ディスプレイ選択・出力 ON / OFF トグル、MIDI デバイス接続状態、現在 FPS・フレームタイム、非同期エラー通知領域。

### 7.2 フォールバック操作

- MIDI コントローラ不調・未接続時に備え、**マウスおよびキーボードショートカットで MIDI 制御対象の全機能を代替操作**できること。

### 7.3 素材読み込み・状態保存と復帰

- 起動時に**指定フォルダ**または**プロジェクト設定ファイル（TOML / JSON）**からクリップ一覧を自動ロードすること。
- UI への**ドラッグ＆ドロップ**による素材追加に対応すること。
- クリップ配置・レイヤー設定・出力先設定等の現在状態を自動保存し、万一のアプリ再起動時にも直前の本番状態へ即座に復帰できること。

## 8. パフォーマンス・負荷超過時の振る舞い

- **目標性能**: FHD（1920×1080）60fps の HAP 動画 4 本同時デコード＋レイヤー合成＋マスターエフェクト適用状態で 60fps を維持すること。
- **負荷超過時のデグレード方針**:
  - 特定レイヤーの I/O・デコードがフレーム期限に間に合わない場合、該当フレームをスキップして直前の有効フレームを保持する。
  - レンダリングループ自体はデコード待ちでブロックせず、60fps の出力送出を継続してフリーズや遅延蓄積を防ぐ。

## 9. 耐障害性・クラッシュ防止仕様

### 9.1 異常系ごとの隔離・復旧ルール

| 想定する異常 | 振る舞い・復旧方針 |
| --- | --- |
| 破損ファイル・未対応フォーマット | 読み込み時に検証して拒否し、該当スロットのみエラー表示。起動や他クリップ再生を止めない。 |
| 再生中のファイル削除・移動・I/O エラー | 該当レイヤーのみ安全に停止・無表示化し、他レイヤーおよびマスター出力を継続する。 |
| 外部ディスプレイ（HDMI 等）の抜去・解像度変更 | 出力ウィンドウを安全に待機状態へ移行し、クラッシュさせない。再接続時に自動またはワンクリックで出力復帰する。 |
| MIDI デバイスの抜去・接続エラー | MIDI 入力のみ一時停止し、バックグラウンドで自動再接続を試行する。UI・キーボード操作は継続可能。 |
| GPU デバイスロスト / Surface Lost | サーフェスおよび描画パイプラインの再生成を試行する。復旧不能な場合も操作画面を維持し通知する。 |

### 9.2 実装・運用ガードレール

- **パニック禁止方針**: 本番実行パスでの `unwrap()` / `expect()` / `panic!()` を禁止し、Clippy リント（`clippy::unwrap_used`, `clippy::expect_used`, `clippy::panic` 等）で機械的に検査する。
- **スレッド境界の隔離**: デコード・ファイル I/O・MIDI 受信はワーカースレッドに分離し、境界でエラー隔離と `std::panic::catch_unwind` によるパニック捕捉・ワーカー再起動を行う。
- **ノンブロッキングなエラー通知**: 異常発生時にモーダルダイアログを出して描画や操作を止めず、UI 上の非同期トースト通知およびローカルログファイルへの記録を行う。
- **誤操作による終了防止**: 終了操作（`Cmd+Q` / `Alt+F4` / ウィンドウ閉じるボタン）に対して終了確認ガードを設け、ライブ中の意図しないアプリ終了を防ぐ。

## 10. スコープ管理（11/28 版）

### Must（11/28 までに必須）

- Windows / macOS 両対応ビルド（開発 Windows、本番 macOS 動作確認）
- HAP（`Hap` / `Hap Alpha` / `Hap Q`）＋静止画（PNG / JPEG）の純 Rust デコード・ストリーミング再生
- 最大 4 レイヤー同時再生・合成（不透明度・5 種ブレンドモード・速度/逆再生/リトリガー）
- マスターシェーダーエフェクト 4 系統＋ブラックアウト
- 外部ディスプレイへの FHD 60fps ボーダーレス全画面出力
- 固定マッピングによる MIDI（Note / CC）制御＋自動再接続
- サムネイル付きコントロール UI、キーボード/マウス代替操作、状態自動保存・復帰
- 第 9 章に記載した異常系耐性・パニック禁止ガードレール・終了確認ガード

### Out of Scope（11/28 以降の検討事項）

- H.264 / H.265 / ProRes 等の汎用動画コーデック直接デコード（FFmpeg 等）
- `Hap Q Alpha` 対応、ピンポン再生、イン/アウト点トリム
- UI 上の MIDI Learn 機能、MIDI Clock（BPM 同期）、MIDI Out（コントローラ LED フィードバック）
- Syphon / Spout / NDI 出力
- レイヤー個別エフェクト、ユーザー定義 WGSL カスタムシェーダー読み込み
- OS プロセス外からの外部ウォッチドッグ（自動再起動ランチャー）
